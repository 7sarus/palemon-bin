# llm.md — palemon-bin

Arch PKGBUILDs for Pale Moon (gtk3 + gtk2), built in GitHub Actions. No local builds.

## Layout

```
palemoon-gtk3/PKGBUILD, palemoon.desktop, palemoon-bin.desktop, palemoon.sh
palemoon-gtk2/  (same files)
.github/workflows/build.yml
```

## State

- Version pinned: **35.0.2** (upstream latest as of 2026-10-09)
- Remote: `https://github.com/7sarus/palemon-bin` (public)
- `main` is the default branch; CI pushes PKGBUILD bumps back to it

## Conventions

- Package names: `palemoon-gtk3` / `palemoon-gtk2`. Both `provides=('palemoon')`
  and conflict with each other and with Arch's `palemoon`.
- `source=` uses `download.php?mirror=us&bits=64&type=linuxgtk{2,3}`; it 303-redirects
  to a versioned mirror path, so no URL edits are needed on bump.
- `sha256sums` are generated by `makepkg -g` in CI from the download page's
  checksum list, not hand-maintained.
- Browser payload installs to `/usr/lib/palemoon/`, launcher at `/usr/bin/palemoon`
  wrapping `run-mozilla.sh`.
- gtk3 package also installs `gtk2/libmozgtk.so` (Flash support) → depends on `gtk2`.

## Workflow

`build.yml` runs on: push to main touching the package dirs, weekly cron (Mon 04:23 UTC),
and `workflow_dispatch` (with optional `publish`).

Trigger locally:
```sh
gh workflow run build.yml -f publish=true
```

## Gotchas

- Directory `palmon` but package repo is `palemon-bin`. Intentional.
- Upstream tarball magic is XZ despite `.tar.xz`; `tar -tJf` needed
  (auto-detect misidentifies it as bzip2 mid-stream).
- Both gtk2 and gtk3 tarballs have a top-level `palemoon/` dir, no version dir.
- `latest` version parse uses `Hashes for release <ver>` from download.shtml;
  there is no directory index on the mirrors (403).
